# หาเคสคล้าย (Similar case)

ปุ่ม Action ใน **UroBase** และ **Consult** (เลือก entry) หาการผ่าตัดในอดีตที่คล้ายเคสนี้ 10 อันดับ แล้วแสดง Op ที่พบบ่อย เช่น `URSL 6/10` พร้อมรายการ 10 เคส (ชื่อ, HN, วันที่, อายุ, เพศ, library, Dx, Op, LOS) กด "ดูทีละเคส" แล้วแต่ละเคสมีปุ่ม เปิด (เปิด entry นั้น) / ถัดไป / ปิด (ปุ่มที่สร้างด้วย `ui().button()` ใน dialog กดแล้วไม่เรียกคำสั่ง จึงไม่ใช้) ทำงานในมือถือทั้งหมด ไม่ใช้อินเทอร์เน็ต ไม่เพิ่มหรือแก้ field

## ติดตั้ง

สร้าง Action ระดับ entry (Entry view card) ทั้งใน UroBase และ Consult เลือก JavaScript library `UroObj.js`, `MyDate.js`, `SimilarCase.js` แล้วใส่ในช่อง script:

```js
simc.run(entry());
```

## ทำงานอย่างไร

เทียบกับทุก entry ใน UroBase + Backup ที่ Status = Done และมี Dx โดยไม่นับคนไข้คนเดียวกัน คะแนนรวม:

| ส่วน | น้ำหนัก | วิธีเทียบ |
|---|---|---|
| Dx | 0.65 | TF-IDF ของตัวอักษร 2-4 ตัว (ตัด Rt/Lt, ขยายคำย่อ UC, RC, VC, BPH, AUR, DJ) |
| Underlying + PastHx (300 ตัวแรก) + InvResult (200 ตัวแรก) | 0.20 | แบบเดียวกับ Dx |
| อายุ | 0.10 | ต่างกัน 0 ปี = เต็ม, 30 ปีขึ้นไป = 0 |
| ขนาดนิ่วใน Dx (mm/cm) | 0.05 | ต่างกัน 0 mm = เต็ม, 10 mm ขึ้นไป = 0 |
| เพศเดียวกัน (จากคำนำหน้าชื่อใน Patient) | 0.05 | ยังไม่ได้ทดสอบ เพราะข้อมูลทดสอบไม่มีชื่อ |

ข้อความถูกตัด HN และวันที่ออกก่อนเทียบ Op นับรวมกันโดยไม่สนข้าง (ใช้ OperationList ถ้ามี ไม่มีใช้ Op)

## ผลทดสอบกับข้อมูลเดิม (2026-10-31)

สุ่ม 600 การผ่าตัด หาเคสคล้าย 10 อันดับจากคนไข้อื่น ดูว่า Op ที่พบบ่อยสุดตรงกับ Op จริงไหม

| วิธี | Op ที่พบบ่อยสุดตรง | Op จริงอยู่ใน 10 อันดับ |
|---|---|---|
| Dx ตรงตัว | 59% | 81% |
| สคริปต์นี้ (ไม่รวมเพศ) | 63% | 85% |
| embedding bge-m3 / e5-large ทั้งสรุปเคส | 55% | 80% |
| embedding + สคริปต์นี้ | 62-64% | 84-85% |

embedding ไม่ได้ดีกว่า จึงใช้วิธีนี้ซึ่งรันในมือถือได้

## ความเร็วและไฟล์ใน /Workload

ครั้งแรกบนมือถือ (~5,460 ผ่าตัด) ใช้ราว 23 วินาที (อ่าน entry 11.8 + คำนวณ 11.0) จึงทำให้เร็วขึ้นดังนี้

- **คำนวณ**: Dx ที่ซ้ำกันคำนวณครั้งเดียว (5,434 ผ่าตัดมี Dx ไม่ซ้ำ 748 แบบ) และเทียบประวัติเฉพาะ 300 เคสที่คะแนนส่วนอื่นสูงสุด ทดสอบกับ CSV ได้ 61.7% / 85.2% (เดิม 62.7% / 84.7% ต่างกันในช่วงคลาดเคลื่อน)
- **อ่าน**: `simcase.json` เก็บข้อมูลที่ใช้เทียบของทุกผ่าตัด (ไม่มีชื่อ/HN) ครั้งต่อไปอ่าน entry ใหม่เฉพาะที่ `lastModifiedTime` เปลี่ยน สร้างใหม่ทั้งหมดทุก 7 วัน (เผื่อแก้วันเกิด/ชื่อใน Patient ซึ่งไม่ทำให้เวลาแก้ไขของการผ่าตัดเปลี่ยน) ลบไฟล์นี้ได้ถ้าอยากสร้างใหม่ทันที
- **จำผลล่าสุด**: `simcase_last.json` เก็บ id ของ 10 เคส กดซ้ำที่ entry เดิม (ที่ยังไม่ได้แก้) ขึ้นทันที ปุ่ม "ดูต่อ เคส n" ต่อจากเคสที่กดเปิดล่าสุด, "คำนวณใหม่" คำนวณอีกครั้ง

log บอกเวลา: `read` = อ่าน entry/cache (ในวงเล็บคือจำนวน entry ที่อ่านใหม่), `compute` = คำนวณ
