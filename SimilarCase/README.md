# หาเคสคล้าย (Similar case)

ปุ่ม Action ใน **UroBase** และ **Consult** (เลือก entry) หาการผ่าตัดในอดีตที่คล้ายเคสนี้ 10 อันดับ แล้วแสดง Op ที่พบบ่อย เช่น `URSL 6/10` พร้อมรายการ 10 เคส (วันที่, อายุ, เพศ, Dx, Op, LOS) ทำงานในมือถือทั้งหมด ไม่ใช้อินเทอร์เน็ต ไม่เพิ่มหรือแก้ field

## ติดตั้ง

สร้าง Action ระดับ entry (Entry view card) ทั้งใน UroBase และ Consult เลือก JavaScript library `UroObj.js`, `MyDate.js`, `SimilarCase.js` แล้วใส่ในช่อง script:

```js
simc.run(entry());
```

## ทำงานอย่างไร

เทียบกับทุก entry ใน UroBase + Backup ที่ Status = Done และมี Dx โดยไม่นับคนไข้คนเดียวกัน คะแนนรวม:

| ส่วน | น้ำหนัก | วิธีเทียบ |
|---|---|---|
| Dx | 0.65 | TF-IDF ของตัวอักษร 2-4 ตัว (ตัด Rt/Lt, ขยายคำย่อ UC, RC, VC, BPH, AUR, DJ) |
| Underlying + PastHx (300 ตัวแรก) + InvResult (200 ตัวแรก) | 0.20 | แบบเดียวกับ Dx |
| อายุ | 0.10 | ต่างกัน 0 ปี = เต็ม, 30 ปีขึ้นไป = 0 |
| ขนาดนิ่วใน Dx (mm/cm) | 0.05 | ต่างกัน 0 mm = เต็ม, 10 mm ขึ้นไป = 0 |
| เพศเดียวกัน (จากคำนำหน้าชื่อใน Patient) | 0.05 | ยังไม่ได้ทดสอบ เพราะข้อมูลทดสอบไม่มีชื่อ |

ข้อความถูกตัด HN และวันที่ออกก่อนเทียบ Op นับรวมกันโดยไม่สนข้าง (ใช้ OperationList ถ้ามี ไม่มีใช้ Op)

## ผลทดสอบกับข้อมูลเดิม (2026-10-31)

สุ่ม 600 การผ่าตัด หาเคสคล้าย 10 อันดับจากคนไข้อื่น ดูว่า Op ที่พบบ่อยสุดตรงกับ Op จริงไหม

| วิธี | Op ที่พบบ่อยสุดตรง | Op จริงอยู่ใน 10 อันดับ |
|---|---|---|
| Dx ตรงตัว | 59% | 81% |
| สคริปต์นี้ (ไม่รวมเพศ) | 63% | 85% |
| embedding bge-m3 / e5-large ทั้งสรุปเคส | 55% | 80% |
| embedding + สคริปต์นี้ | 62-64% | 84-85% |

embedding ไม่ได้ดีกว่า จึงใช้วิธีนี้ซึ่งรันในมือถือได้

## ความเร็ว

ทดสอบด้วย Rhino แบบ interpreted บนคอมพิวเตอร์ ~5,400 เคส ใช้ประมาณ 6-10 วินาที บนมือถืออาจช้ากว่านี้ (ยังไม่ได้วัด) ดูเวลาจริงได้ที่หัว dialog และใน log (`read` = อ่าน entry, `compute` = คำนวณ)
